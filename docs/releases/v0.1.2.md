# AsySounds v0.1.2 — Performance & security hardening

## What's new
- A repeatable full-DSP offline benchmark covering RNNoise, voice processing, and presence EQ over 60 seconds of synthetic audio.
- Validation notes for the measured offline processing budget and limitations.

## Performance improvements
- Recalculate high-pass and makeup-gain settings only when the user actually changes voice controls, instead of on every 10 ms audio frame.
- Read the monitoring state once per output callback rather than once per sample, preserving smooth mute/unmute transitions.
- Reduce live UI telemetry polling from ~8.3 to 4 updates/second, or 1/second in the background; overlapping status requests are prevented.

## Security and reliability
- Fix portable Windows launch: use the production Tauri CLI build to bundle the frontend, and ship the required x64 WebView2Loader.dll beside the executable.
- Fix the Microphone page's responsive layout after adding the two output modes, so device selectors and neural controls are not overlapped.
- Enable a restrictive production Content Security Policy for the bundled Tauri WebView, including only local scripts/assets, IPC, and in-memory A/B audio.
- Preserve explicit route selection, local-only DSP, and Windows/Sonar defaults.
- Validate input/processed audio with finite-sample tests, Rust formatting, Clippy, core/Tauri tests, and TypeScript/Vite builds.

## Compatibility
- Windows x64, requires WebView2.
- The virtual microphone route needs an existing, separately installed VB-CABLE-compatible driver. Nothing is installed or configured automatically.
- Portable executable with WebView2Loader.dll, no console on GUI launch. WebView2 Runtime must already be installed.
- Not yet a complete Sonar replacement; virtual Game/Chat/Media/Aux strips remain prototypes.

## Known limitations
- Offline DSP timing does not measure actual device-to-Discord/OBS latency, scheduler jitter, or stream stability.
- Real microphone tests are still required for simultaneous claps/clicks and speech; 100% removal is not guaranteed.
- A/B capture intentionally mutes the selected output and stops the route at the comparison step.
- Executable is not digitally signed.
